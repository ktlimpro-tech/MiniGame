# 🐛 03. 동일 브라우저 다중 창(탭) 접속 시 방장 소멸 버그 원인 분석 및 해결

> **작성 일시**: 2026-11-03  
> **프로젝트**: `2026-MiniGame`  
> **관련 파일**: [public/js/app.js](file:///d:/My%20Web%20App/2026-MiniGame/public/js/app.js), [test/room.test.js](file:///d:/My%20Web%20App/2026-MiniGame/test/room.test.js)

---

## 1. 발생했던 문제 현상
* `http://localhost:3000/`에서 방 생성 후 링크(`?room=3SHY`)를 복사하여 **같은 브라우저의 다른 창(탭)**에서 접속.
* 나중에 들어온 참가자가 참여하기를 누르자, **기존 방장이 사라지고 나중에 들어온 1명만 대기실에 남는 현상** 발생 (인원수가 2명이 아닌 1명으로 유지).

---

## 2. 근본 원인 분석 (Root Cause)

1. **`localStorage`의 도메인 단위 전역 공유 특성**:
   * 기존 클라이언트는 식별 토큰을 브라우저의 `localStorage.getItem('minigame_token')`에 단일 키로 저장하고 있었습니다.
   * `localStorage`는 같은 브라우저 내에서 열린 모든 창/탭 간에 **100% 동일하게 공유**됩니다.
   
2. **참여 시 방장의 토큰이 그대로 전송됨**:
   * 창 1(방장): 방 생성 시 `minigame_token = Token_A` 발급 및 저장.
   * 창 2(참가자): 같은 도메인이므로 `localStorage`에서 `Token_A`를 그대로 읽어옴.
   * 창 2에서 닉네임 입력 후 `joinRoom` 전송 시, **방장의 토큰(`Token_A`)을 들고 서버에 입장 요청**.

3. **서버의 재연결(Reconnect) 로직 오작동**:
   * 서버(`Room.js`)는 `Token_A`가 들어오자 *"아, 방장이 새로고침해서 다시 들어왔구나!"*라고 판단.
   * 기존 방장의 정보를 창 2의 정보(새 닉네임 및 새 소켓)로 **덮어쓰기(Overwrite)** 처리함.
   * 결과적으로 방장이 참가자로 둔갑하여 총인원이 1명만 남게 됨.

---

## 3. 적용된 해결책 (Solution)

### 1) `sessionStorage` 기반의 창/탭 독립 격리 적용
* `localStorage` 대신 **`sessionStorage`**를 도입했습니다.
* `sessionStorage`는 **브라우저의 각 탭(창)마다 완전히 독립된 저장 공간**을 가집니다.
  * 창 1(방장)의 토큰: 창 1의 `sessionStorage`에만 보관.
  * 창 2(참가자)의 `sessionStorage`: 비어 있음(`null`) ➔ 서버에 신규 플레이어로 정상 등록 (`Token_B` 발급).
* 탭을 새로고침(F5)해도 `sessionStorage`는 보존되므로 **새로고침 시 재연결(Reconnect) 기능은 100% 정상 작동**합니다.

### 2) 방 코드별 토큰 격리 (`minigame_token_${roomCode}`)
* 세션 토큰 키를 방 코드별로 분리하여 한 브라우저 세션에서 다른 방으로 이동하더라도 토큰이 뒤섞이지 않도록 방어했습니다.

### 3) 기존 잔여 `localStorage` 토큰 자동 정리
* 브라우저 초기 로드 시 기존에 전역으로 남아있던 `localStorage.removeItem('minigame_token')`을 실행하여 이전 캐시로 인한 간섭을 제거했습니다.
