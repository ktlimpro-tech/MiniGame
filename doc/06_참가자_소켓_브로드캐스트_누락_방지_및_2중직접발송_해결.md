# 📡 06. 참가자 소켓 브로드캐스트 누락 방지 및 2중 안전 발송 구축 보고서

## 1. 발생했던 문제 현상
* 3명의 플레이어가 게임 중, 방장(첫 번째 사용자)이 이빨 하나를 눌렀을 때:
  * 방장 화면에서는 락이 걸리고 멈추었으나,
  * **다른 참가자 화면으로 턴(`toothPressed` 이벤트)이 전달되지 않아 참가자 화면이 대기 상태로 그대로 멈춰있는 현상** 발생.

---

## 2. 근본 원인 분석 (Root Causes)

1. **Socket.io 룸 소속 누락 (Transport Upgrade & Reconnect)**:
   * Socket.io는 HTTP Long-Polling ➔ WebSocket으로 연결 방식이 전환(Upgrade)되거나 백그라운드 전환 시 일시적인 재연결이 발생합니다.
   * 이때 소켓 ID가 변경되면서 기존 서버 룸(`io.to(roomId)`) 소속에서 누락될 수 있습니다.
2. **단순 `io.to(roomId)` 브로드캐스트의 한계**:
   * 소켓 룸에 정확히 매핑되지 않은 클라이언트 소켓은 `io.to(roomId).emit()` 메시지를 수신하지 못했습니다.
3. **재연결 시 방 자동 재참가(Rejoin) 부재**:
   * 클라이언트 소켓이 재연결되었을 때 서버에 본인의 방과 토큰을 알려 소켓 룸을 복원하는 로직이 없었습니다.

---

## 3. 적용된 해결책 (Solutions)

### 1) 서버 2중 안전 브로드캐스트 (`broadcastToRoom`) 도입 ([server/server.js](file:///d:/My%20Web%20App/2026-MiniGame/server/server.js))
* 단순히 `io.to(roomId).emit()`만 호출하던 방식에서 벗어나:
  1. 표준 소켓 룸으로 브로드캐스트 발송.
  2. 동시에 `room.players`에 등록된 **모든 플레이어의 소켓 객체를 직접 조회하여 `s.join(roomId)` 강제 재확인 + `s.emit()` 개별 직접 발송** 수행!
  * ➔ 어떠한 소켓 재연결이나 룸 누락 상태에서도 **모든 참가자에게 100% 이벤트 도달 보장**.

### 2) 클라이언트 자동 룸 재참가(Rejoin) 시스템 ([socketManager.js](file:///d:/My%20Web%20App/2026-MiniGame/public/js/socketManager.js), [app.js](file:///d:/My%20Web%20App/2026-MiniGame/public/js/app.js))
* 클라이언트의 `socket.on('connect')` 이벤트에서 현재 참여 중인 방 코드와 토큰이 있다면, 서버의 `rejoinRoom`을 즉각 호출하여 소켓 ID를 최신화하고 룸에 다시 바인딩하도록 구현했습니다.

### 3) 인게임 이빨 시각 피드백 명확화
* 이미 누른 이빨은 회색 쏙 들어간 형태와 함께 **`안전`** 텍스트를 명확히 표시하여 누가 보더라도 상태를 즉시 인지할 수 있도록 개선했습니다.
