# 🐊 05. 이빨 선택 후 턴 전환 지연 및 연타 방지 버그 분석 및 해결 보고서

## 1. 발생했던 문제 현상
* 3명의 플레이어가 게임 진행 중, 첫 번째 사용자가 이빨 하나를 눌렀을 때:
  1. 다음 사용자의 턴으로 매끄럽게 넘어가지 않음.
  2. 첫 번째 사용자가 계속해서 다른 이빨들을 연달아 누를 수 있는 상태가 됨.

---

## 2. 근본 원인 분석 (Root Causes)

1. **클릭 즉시 다른 이빨 차단(Lock) 부재**:
   * 기존 코드는 클릭한 **그 이빨 하나만 `disabled` 처리**하고 나머지 이빨들은 열려 있었습니다.
   * 서버 통신이 오가는 찰나의 시간(수십~수백 ms)이나 소켓 브로드캐스트 대기 시간 동안 사용자가 다른 이빨을 누를 수 있었습니다.
2. **소켓 브로드캐스트 대기 의존 및 비동기 지연**:
   * 본인이 이빨을 눌렀을 때, 소켓 서버로부터 `toothPressed` 브로드캐스트가 돌아오기 전까지는 자신의 화면 상태가 갱신되지 않았습니다.
3. **Web Audio API 예외로 인한 자바스크립트 중단 가능성**:
   * 브라우저의 오디오 정책(Autoplay restriction)에 의해 `playSafe()` 등에서 예외가 발생할 경우, 그 뒤에 있던 `renderCrocodileGame()` 렌더링 호출이 통째로 멈춰버리는 문제가 있었습니다.
4. **서버 측 룸 코드 대소문자 미처리**:
   * `RoomManager.handleGameAction`에서 전달받은 `roomCode`의 대소문자 불일치 가능성이 존재했습니다.

## 3. 적용된 해결책 (Solutions)

### 1) 이빨 선택 즉시 '전체 연타 방지 락(Lock)' 적용
* [app.js](file:///d:/My%20Web%20App/2026-MiniGame/public/js/app.js)에서 이빨을 하나 누르는 순간:
  ```javascript
  els.teethGrid.style.pointerEvents = 'none'; // 전체 이빨 그리드 즉시 터치 차단
  ```
* 본인이 이빨을 하나 선택하면 서버 판정이 완료될 때까지 **다른 이빨을 추가로 터치할 수 없도록 물리적 차단**을 걸었습니다.

### 2) 서버 응답(Ack) 즉시 로컬 화면 최신화 (0ms 반응성)
* 소켓 브로드캐스트를 기다리지 않고, 서버로부터 성공 콜백(`res.success === true`)이 오면 반환된 최신 룸 상태(`res.data.room`)를 바탕으로 **내 화면의 턴을 즉시 다음 사람 차례로 갱신**합니다.
* 실패 시에는 락을 풀고 원래대로 복원합니다.

### 3) 오디오 및 진동 시스템 예외 안전망 구축
* [audio.js](file:///d:/My%20Web%20App/2026-MiniGame/public/js/audio.js)의 모든 메서드(`playClick`, `playSafe`, `playChomp`, `playTurn`) 내부를 `try ... catch`로 안전하게 감싸서, 브라우저의 오디오 정책 에러가 나더라도 게임 렌더링과 턴 전환에 일절 영향을 주지 않도록 완벽 격리했습니다.

### 4) 서버 소켓 조인 안전성 및 로깅 강화
* [server/server.js](file:///d:/My%20Web%20App/2026-MiniGame/server/server.js)에서 `gameAction` 수신 시 `socket.join(result.roomId)`를 재확인하고, 콘솔에 누가 몇 번 이빨을 눌렀으며 다음 턴이 누구인지 명확히 출력되도록 개선했습니다.
* [server/models/RoomManager.js](file:///d:/My%20Web%20App/2026-MiniGame/server/models/RoomManager.js)에서 `roomCode.toUpperCase()`로 대소문자 불일치 문제를 원천 차단했습니다.
