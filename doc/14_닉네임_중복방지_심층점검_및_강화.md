## 1. 문제 원인 분석

테스트 중 중복 닉네임이 그대로 노출되거나 반영되지 않았던 원인을 심층 추적한 결과, 다음 3가지 핵심 요인이 확인되었습니다.

1. **서버 프로세스 미재시작 (가장 결정적 원인)**
   - `package.json`의 `npm start`가 기존에 단순 `node server/server.js`로 실행되고 있었습니다.
   - 따라서 터미널에서 `npm start`를 띄워둔 상태에서 소스 코드가 수정되어도, **메모리에 기존 서버 코드가 그대로 실행 중**이어서 수정된 중복 체크 로직이 적용되지 않았습니다.
   - **조치**: `npm start` 및 `dev` 스크립트를 Node 내장 감시 모드인 `node --watch server/server.js`로 업그레이드하여, 코드 수정 시 즉시 서버가 자동 리로드되도록 개선했습니다.

2. **재연결(Reconnect) 시 닉네임 중복 체크 누락**
   - 기존에는 재연결 플레이어가 닉네임을 변경해서 들어올 경우 `existing.nickname = nickname;`으로 단순 대입하여, 다른 사람의 닉네임과 겹칠 수 있는 허점이 있었습니다.
   - **조치**: 재연결 시에도 `generateUniqueNickname(nickname, existing.token)`을 호출하여 중복 검사를 반드시 통과하도록 방어했습니다.

3. **공백 및 영문 대소문자(Case-Insensitive) 불일치**
   - 앞뒤 공백이 있거나 영문 대소문자(`Admin` vs `admin`)가 다를 경우 중복으로 감지하지 못하는 문제가 있었습니다.
   - **조치**: `toLowerCase()` 정규화 및 `trim()`을 적용하여 어떤 입력 형태라도 정확히 중복을 감지하고 `(2)`, `(3)` 번호를 순차 부여하도록 강화했습니다.

4. **클라이언트 입력창 및 로컬스토리지 동기화**
   - 참가자가 "홍길동"으로 들어왔을 때 서버에서 "홍길동(2)"를 부여했더라도, 클라이언트 로컬 입력창에는 이전 입력값이 남아 혼란을 줄 수 있었습니다.
   - **조치**: 서버 응답 수신 즉시 클라이언트 `els.inputNickname.value`와 `localStorage`를 실제 확정된 닉네임으로 즉시 동기화했습니다.
