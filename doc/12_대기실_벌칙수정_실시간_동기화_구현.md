## 1. 구현 개요 및 문제 분석

### 기존 동작의 한계
- 기존에는 대기실에서 방장이 "걸린 사람 벌칙" 인풋창(`els.inputPenalty`)의 내용을 바꾸더라도, **'게임 시작하기' 버튼을 누르는 순간에만** 서버로 벌칙 설정(`updateSettings`)이 전송되었습니다.
- 또한 대기실 렌더링 함수(`renderLobby`)에서도 방의 `room.settings.roles[0]`을 인풋창에 반영해주는 코드가 누락되어 있어, 다른 참가자들은 게임이 시작되기 전까지 방장이 벌칙을 무엇으로 바꿨는지 알 수 없었습니다.

### 개선된 실시간 동기화 흐름
1. **방장의 타이핑 즉시 감지 (Debounce 200ms)**:
   - 방장이 벌칙 입력창에 타이핑할 때 `input` 이벤트가 발생하면, 200ms 디바운스를 거쳐 소켓 `updateSettings` 이벤트를 즉시 발송합니다.
   - 포커스를 잃거나(`blur`) 엔터/변경 완료(`change`) 시에는 지연 없이 즉시 동기화합니다.
2. **전체 참가자 브로드캐스트 (`roomUpdated`)**:
   - 서버는 변경된 벌칙 설정을 방 내 모든 접속자에게 실시간 브로드캐스트합니다.
3. **참가자 화면 자동 렌더링**:
   - 일반 참가자들의 화면에서는 벌칙 입력창의 내용이 실시간으로 동기화되어 즉시 표시됩니다.
4. **방장의 커서 튐(Flicker/Jumping) 방지**:
   - 방장이 타이핑하는 도중 서버로부터 소켓 이벤트(`roomUpdated`)가 도착하더라도, 현재 포커스된 상태(`document.activeElement === els.inputPenalty`)일 때는 입력창을 덮어쓰지 않아 부드럽고 매끄러운 한글/영문 타이핑이 보장됩니다.
5. **상태 안내 배지 연동**:
   - 방장에게는 `방장 설정 가능`, 일반 참가자에게는 `방장이 실시간 설정 중`으로 안내 문구가 반응형으로 표시됩니다.
